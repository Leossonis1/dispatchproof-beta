# DispatchProof Positioning — V2.46.11

## Core line
**Your back office tracks the job. DispatchProof runs it.**

## Product role
DispatchProof is the field-execution layer for construction deployment: PM execution, crews, subcontractors, readiness, documents, conflicts, field updates, and completion.

It is not intended to replace accounting, invoicing, estimating, purchasing, payroll, or a full ERP/business system.

## Integration model
**Back office → DispatchProof → Back office**

Bring only the operational job information needed to execute the work. Run the field workflow in DispatchProof. Return a clean completion/status signal to the back-office system for billing and closeout.

## Quickbase wording before live beta testing
Use: **“Quickbase integration planned”** or **“Quickbase connector planned for private beta.”**

Do not use: **“Integrates with Quickbase”** until a real Quickbase customer/account has completed end-to-end beta testing.

## Important message
No external back-office system is required. DispatchProof works standalone. Integrations are optional companions for companies that already use another system of record.
